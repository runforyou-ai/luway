# Windows 端到端验证

本文描述从源码准备到 Windows 实机验收、证据归档和环境恢复的流程。通用约定见 [AGENTS.md](../../AGENTS.md)，构建入口见 [Windows Taskfile](Taskfile.yml)。每轮按改动范围选择业务场景，并记录实际执行结果。

## 1. 确定源码和执行环境

记录待验证提交、工作区未提交改动及其文件校验值。验证未提交内容时，源码快照须包含这些内容，并记录所包含的文件；构建产生的图标、绑定和依赖文件在独立快照或工作树中检查。

代码目录随构建工具所在系统选择：

| 构建方式 | 源码位置 | 验证位置 |
| --- | --- | --- |
| Windows 原生工具链 | Windows 本地目录 | Windows 交互式桌面 |
| WSL2 交叉编译 | Ubuntu 文件系统中的独立目录，如 `~/code/luway-e2e-<标识>` | 将 exe 复制到 Windows 独立目录后运行 |

WSL 源码快照记录来源提交和同步时间。远端已有仓库、开发数据库和安装目录保留原状；构建快照只携带所需文件，服务端凭据留在实际运行服务端的环境中。

远程准备时确认以下信息：

- Windows 用户、系统与 CPU 架构、WebView2 版本、屏幕缩放、当前桌面会话和已有 Luway 进程。
- WSL 发行版、是否运行、Windows interop 是否可用，以及非交互 SSH 环境中 Go、Node、Wails CLI、编译器和打包工具的实际路径与版本。
- 对照 `go.mod`、`frontend/package.json` 校验 Wails 精确版本；目标机器的历史构建目录仅作为工具来源，版本以待验证源码为准。

通过 Windows SSH 启动的进程可能位于非交互会话。通过 WSL 调用 Windows PowerShell 后，先比较目标进程与当前用户 `explorer.exe` 的 `SessionId`，再检查真实窗口是否可见。会话编号以实测为准。

## 2. 建立测试数据和系统状态基线

服务端使用该 worktree 的 `PUBLIC_URL` 和公网域名。首次安装场景使用本轮空数据库，通过 Web 完成初始化，再由 Windows 客户端连接和登录。需要独立数据时，为本轮配置数据库、NATS 命名空间、文件目录和所需端口，并记录资源归属；共享 PostgreSQL 和 NATS 实例保持运行。目标端口已有服务时，先核对归属和验证范围，保留其他会话启动的进程；需要调整公网转发时由用户配置 Tunnel。

每个 Windows 测试实例使用独立的 SQLite 与 WebView 数据目录，双账号测试启动两个实例：

| 配置 | 用途 |
| --- | --- |
| `DESKTOP_DATA_DIR` | Luway 桌面端 SQLite 等应用数据 |
| `WEBVIEW2_USER_DATA_FOLDER` | Windows WebView2 用户数据与登录存储 |
| `WAILS_MCP_HOST` | MCP 监听地址，使用回环地址 |
| `WAILS_MCP_PORT` | 每个实例独立的 MCP 端口 |

环境变量仅作用于本轮启动进程及其子进程。启动后核对目录实际创建位置、进程 PID、子进程和端口归属。

### Windows 通知注册

Wails 通知服务启动时会将当前 exe 写入用户注册表。独立 SQLite 与 WebView 目录仍会共享这项系统注册，因此在第一次启动测试程序之前保存基线。

按当前应用名称和 Wails 依赖实现核对以下位置，应用名称取自 `run_native.go` 的 `application.Options.Name`，并结合实际系统语言确认：

- `HKCU\Software\Classes\AppUserModelId\<应用名称>`，包括 `CustomActivator`。
- 该 `CustomActivator` 指向的 `HKCU\Software\Classes\CLSID\<GUID>`，尤其是 `LocalServer32` 默认值。
- `HKCU\SOFTWARE\<应用名称>\NotificationCategories`；通知服务退出时也可能写入分类数据。

记录相关键和值是否存在、原始值和类型。原先不存在的项同样记录为基线；首次启动后记录本轮新建的 GUID 和键。涉及安装或其他系统集成时，按实际行为补充快捷方式、协议或文件关联基线。

恢复时先停止本轮程序，核对当前值仍属于本轮变更，再恢复原值或删除本轮创建的项。若发现其他程序同时更新这些位置，保留现场并说明冲突。注册表导入会合并内容，本轮新增项需要单独核对清理。缺少启动前快照时，在报告中说明恢复依据和剩余限制。

## 3. 构建与启动

从独立源码根目录执行平台 Task。以下以 amd64 为例，其他架构按目标机器选择：

```bash
# 生成带 MCP 的测试程序。
wails3 task windows:build ARCH=amd64 EXTRA_TAGS=mcp

# 生成正式程序和用户级安装包。
wails3 task windows:package ARCH=amd64 INSTALL_SCOPE=user
```

两个构建阶段分别归档产物和日志，正式构建前清除本轮额外的 MCP 构建标签。核对 exe 的 Windows 目标架构、CGO、Wails 版本、构建标签和 SHA-256；正式产物使用 `production` 标签且不含 `mcp`。

当前非 Windows 平台的标准 Task 使用 `wails-cross` Docker 镜像，可通过 `wails3 task setup:docker` 准备。已有 MinGW 工具链需要复用时，在独立快照中通过本地 Taskfile 调用平台构建任务，记录该适配；`windows:build:native` 是内部任务，需由包装 Task 调用。目标 OS、架构和 CGO 继续由 Task 管理，调用者只传 `ARCH`。

Linux 上安装或构建 Wails CLI 使用 Linux 编译器；MinGW 的 `CC` 仅作用于 Windows 目标构建阶段。SSH 非交互会话须显式准备所需 PATH。自定义 Taskfile 的入口形式为 `wails3 task --taskfile <文件> <任务>`；项目根 Taskfile 带有 `dotenv`，包装任务可通过子命令调用根任务加载环境。

将测试 exe 复制到 Windows 独立目录，设置本轮环境后在已核实的交互式会话启动。源码在 WSL 时，执行 WSL 的普通 `dev:mcp` 会选择 Linux 开发目标；Windows 验收使用 Windows exe，或在 Windows 原生源码目录执行 `wails3 task dev:mcp`。

MCP 经 SSH 转发到控制端，远端保持回环监听。MCP 的回环地址仅用于控制通道，客户端业务请求仍使用 worktree 公网域名。启动后读取 `tools/list` 和 `windows_list`，以当前实例实际暴露的工具参数、窗口名称和编号操作。

## 4. 操作和证据

MCP 用于点击、输入、读取 DOM 和状态断言。每次操作后等待可观察的完成状态，再核对界面；异步调用返回与最终显示分别检查。业务关键步骤通过界面完成，API 创建账号等准备工作单独记入报告。

真实窗口截图可通过 Windows 桌面截图或针对目标 HWND 的 `PrintWindow` 获取，检查图片确实包含目标窗口及 WebView2 内容。记录窗口尺寸和系统缩放；读取物理像素坐标时使用匹配的 DPI 感知设置。DOM 结构快照作为状态证据单独保存。

系统文件选择器、托盘、系统通知和输入法使用 Windows UI Automation 或 Computer Use 操作。文件对话框可能是独立 HWND，分别定位、操作和取证；控件名称与编号通过本轮枚举获取。跨 WSL 传递中文 PowerShell 脚本时，可用 UTF-16LE Base64 的 `-EncodedCommand`，并显式设置输出编码。

### 基础场景

| 场景 | 验收条件 |
| --- | --- |
| 连接与登录 | 公网连接成功；退出回到登录页；再次登录进入正确工作区 |
| 单聊与群聊 | 两个实际 Windows 实例双向收发；接收端保持已打开状态并实时显示消息、输入状态及相关列表更新 |
| 文件附件 | 实际文件选择器选中文件；上传完成后显示预览；发送后另一客户端可读取；下载文件与原文件校验值一致 |
| 工作区切换 | 切换后显示目标工作区数据；原工作区收到消息后，切回显示最终状态 |
| 窗口与托盘 | 默认尺寸、最大化、还原、最小化符合预期；关闭窗口后进程保持运行；实际托盘操作恢复可见窗口和焦点 |
| 重启与正式产物 | 停止 MCP 测试实例，使用同一测试数据启动不含 MCP 的正式 exe；登录状态和历史数据恢复，核心流程可操作 |

窗口最小尺寸以当前源码为准。通过 MCP 强制设置更小尺寸的结果记为额外布局压力检查。正常退出与强制结束后的恢复分别记录；中文文本输入与真实 IME 组合输入分别验证。

按改动范围追加通知点击跳转、安装升级与卸载、语音、AI 执行或客服访客链路。安装包生成只证明打包完成；安装验收须实际执行安装流程并记录结果，已有用户安装的数据和设置纳入恢复计划。

### 常见阻塞

| 现象 | 下一步 |
| --- | --- |
| 公网域名返回 502 | 先检查本轮服务端进程、启动日志和目标监听端口，再检查 Tunnel；记录界面覆盖中断的位置 |
| MCP 可连接但桌面无窗口 | 核对程序 SessionId、用户、窗口可见状态及当前交互桌面 |
| DOM 有内容但截图为空 | 核对 HWND、DPI、窗口状态和捕获方式，取得有效图片后再判断视觉结果 |
| 自动化点击无结果 | 检查焦点、遮罩、实际命中控件与操作后的状态；API 准备数据单独记录，原界面操作保留为待验证 |
| 验证码或授权确认 | 说明当前步骤并等待用户完成，再继续同一流程 |

## 5. 清理与归档

按资源清单清理并逐项核对：

1. 停止本轮 Windows 客户端和 WebView 子进程，再停止本轮服务端、Vite、MCP 与 SSH 转发，确认端口释放。
2. 在程序完全退出后恢复通知注册及其他系统集成基线，检查测试路径残留。通知服务可能在退出时写入注册表。
3. 清理本轮数据库、NATS 命名空间或独立容器、测试上传与下载文件、SQLite 和 WebView 目录；保留共享服务及用户原有资源。
4. 关闭本轮浏览器标签和系统对话框，比较源码状态与基线文件校验值。
5. 归档报告、截图、构建与运行日志、正式产物及校验值。记录保留的源码快照和产物位置，以及再次运行所需的后端条件。

报告至少包括：源码提交与未提交内容、操作系统与工具链版本、实际执行场景及证据、失败和未覆盖项目、构建与安装的分别结论、清理结果与剩余资源。日志和截图中的凭据留在受控的本地证据目录，进入仓库或 PR 的内容须脱敏。
