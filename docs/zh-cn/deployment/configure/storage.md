title: 文件存储
order: 5
---

{{product}} 统一使用 S3 兼容对象存储。首次安装后，平台管理员须在「平台后台 → 系统设置 → 文件存储」完成配置，才能上传附件、头像和知识文档。配置由整个部署共用，所有服务器在 10 秒内生效。

## 上传地址与访问地址

| 字段 | 说明 |
| --- | --- |
| 上传接口地址 | S3 API 的完整地址，服务器和客户端设备都必须能够访问；不能填仅容器内可达的地址 |
| 文件访问地址 | 文件的固定访问地址，可以使用 CDN 或自定义域名，如 `https://cdn.example.com/assets` |
| 区域、存储桶 | S3 区域与存储桶名称 |
| 访问密钥 ID、访问密钥 | 服务端使用的凭据，允许读取、写入、删除对象及创建、列举、上传、完成和中止分片 |
| 路径形式访问 | 使用「接口地址/存储桶」访问 S3 API；自建 S3 服务通常需要开启 |

文件地址为「文件访问地址/对象键」，系统不会再追加存储桶名称。例如访问地址为 `https://cdn.example.com/assets`，对象键为 `workspaces/…/files/….png`，最终地址就是 `https://cdn.example.com/assets/workspaces/…/files/….png`。若直接使用路径形式的存储桶地址，访问地址本身应包含存储桶名称。

客户端使用短期预签名请求直接上传；超过 100 MiB 时由 Uppy 分片上传，并直接请求 S3 合并。服务端核验实际大小与文件类型后确认上传完成。普通文件使用无过期时间的访问地址，聊天历史和 AI 引用不会因上传签名过期而失效。点击下载时可按需签发带原文件名的下载请求，该临时请求不会写入聊天历史。

## 保存校验与访问权限

保存前，服务器会创建随机测试对象，验证凭据写入、读取、删除，以及从文件访问地址匿名读取的实际内容。任一步失败都不保存配置。

推荐使用私有存储桶与具备回源权限的 CDN，让 CDN 匿名提供普通文件。若测试对象在 S3 源站也能匿名读取，仍允许保存，但会提示改用 CDN 并限制源站访问。仅绑定 CDN 域名并不会自动关闭源站公开读取。无法确定源站状态时会给出提示；这不代表整个存储桶的权限已获验证。

普通文件放在 `workspaces/*/files/*`，知识文档原件放在 `workspaces/*/knowledge-documents/*`，持有链接者均可访问。聊天历史、AI 引用与知识预览都使用稳定的「文件访问地址/对象键」，不会因预签名过期失效。不要把整个存储桶设为公开读，也不要允许匿名写入。

## 存储桶跨域设置

浏览器和桌面端直接请求 S3，上传接口须允许应用来源的 `GET`、`PUT`、`POST`、`DELETE`、`HEAD`，允许请求所需的 `Content-Type`、`Cache-Control` 和 `x-amz-*` 头，并向浏览器暴露 `ETag`。桌面端的 WebView 来源也须加入允许来源。访问域名需允许应用读取文件的跨域请求。

连接测试从服务端执行，不能替代浏览器 CORS 验证。保存后应在 Web 和使用中的客户端各上传一个文件；分片验证使用大于 100 MiB 的文件。

## 临时文件清理

选择文件后立即上传为临时文件，保存业务数据时才正式使用。未使用的文件 24 小时后过期，由后台任务删除并中止未完成的分片。建议为存储桶额外配置中止长期未完成分片的生命周期规则，以清理网络故障产生的孤立会话。
