title: 邮件发送

平台管理员在「平台后台 → 系统设置 → 邮件发送」启用邮件，选择一种接入方式，填写发件邮箱和对应参数，然后保存。整个部署共用这份配置，所有服务器在 10 秒内使用新配置。

## 接入方式

| 接入方式 | 配置参数 |
| --- | --- |
| SMTP | 主机、端口、加密方式；需要认证时填写用户名和密码 |
| Amazon SES | AWS 区域、Access Key ID、Secret Access Key |
| Mailgun | 发信域名、US 或 EU 区域、API Key |
| Postmark | Server Token；消息流留空时使用 outbound |
| Resend | API Key |

SMTP 默认使用 587 端口和 STARTTLS，也可选择 SSL/TLS 或不加密。用户名留空表示不认证，并会清除已保存的密码。

使用邮件服务商 API 前，先在服务商处验证发信域名或发件邮箱，并确认账号具有发信权限。Amazon SES 使用 SES v2 API；区域须与已验证的身份一致，沙箱账号还需遵守收件人验证限制。API 方式使用服务商的官方接口地址。

发件人名称留空时使用邀请或通知邮件自带的名称；填写后统一使用该名称。每次发送最多等待 30 秒。

## 保存与测试

密钥不会在读取配置时返回明文。显示「已设置」时，输入框留空保留当前密钥，填写新值会替换它。修改 SMTP 主机或用户名、SES Access Key ID 后，需要重新填写对应密钥。

切换接入方式后，只保存当前方式的参数；原服务商参数和密钥会被清除。关闭邮件发送会保留当前配置，重新开启时必须补齐必填项。

保存后点击「发送测试邮件」，在弹出的模态框中填写「测试收件邮箱」并发送。有未保存的修改时需先保存。发送成功表示邮件服务已接受投递，请继续检查收件箱与垃圾邮件目录；认证失败、发送额度受限、投递被拒绝或超时会分别提示。

凭据保存在部署数据库中，数据库和备份访问权限应与其他服务凭据一并保护。诊断信息与邮件发送错误不包含密钥或邮件正文。

> [!NOTE]
> 从仅支持 SMTP 的版本升级后，需要在此页面重新配置并启用邮件。服务端与客户端应同步更新。

## 使用邮件的功能

- 邀请成员时，服务器向受邀邮箱发送邀请邮件；关闭邮件发送时只给出邀请链接，由邀请人自行转发。
- 网站访客转人工后可以留下邮箱，访客离开后客服回复时，服务器合并发送邮件通知，附带回到原会话的链接。关闭邮件发送时转人工话术不请访客留邮箱，已经排队的通知保留到重新启用后发送。
