检查服务状态，查看日志并处理诊断信息。

## 健康检查

服务端提供两个健康检查地址，都支持 `GET` 和 `HEAD`。`GET` 返回 JSON，`HEAD` 只返回相同的状态码和响应头：

| 地址 | 用途 |
| --- | --- |
| `/healthz` | 进程存活检查。服务端在运行就返回 `200` 和 `{"status":"ok"}`，不检查依赖，适合作为容器或进程管理器的存活探针 |
| `/readyz` | 就绪检查。服务端在 3 秒内查询一次 PostgreSQL，成功时返回 `200` 和 `{"status":"ready"}`，失败时返回 `503` 和 `{"status":"unavailable"}`，适合作为负载均衡摘除节点的依据 |

NATS、对象存储和授权服务的状态不影响健康检查，可以在「设置 → 平台 → 运行状态」查看，见[运行状态与诊断](/docs/zh-cn/guide/admin/diagnostics/)。

## 日志

服务端把日志输出到标准输出和标准错误，不写日志文件。容器部署时用容器运行时查看，例如 `docker logs <容器名>`；以 systemd 服务运行时用 `journalctl -u <服务名>` 查看。需要长期保存时，由容器运行时或系统日志服务收集。

## 诊断导出

平台管理员可以在「运行状态」页导出诊断信息，交给运维人员或技术支持排查。文件包含各服务器的状态和配置、外部依赖、数据库版本、后台任务错误和模型供应商的近期结果，不包含密码、密钥、业务内容和日志，详见[运行状态与诊断](/docs/zh-cn/guide/admin/diagnostics/)。

## 远程上报

服务端默认每分钟向授权服务上报账号数、工作区数等运行指标，只包含计数，平台管理员可以关闭，详见[运行状态与诊断](/docs/zh-cn/guide/admin/diagnostics/)。诊断信息不会自动上报。
