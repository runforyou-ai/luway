## 绑定渠道身份

客户通过 Telegram 直接连接等渠道发来消息时，请求中不携带签名身份。业务系统确认渠道账号属于某个用户后（例如通过一次性绑定链接），调用渠道身份接口把该账号设为已验证；用户解除绑定时调用同一地址撤销。

```http
PUT /api/public/channels/<渠道编号>/identities/<外部编号>/verification
Authorization: Bearer <签名身份>
```

```http
DELETE /api/public/channels/<渠道编号>/identities/<外部编号>/verification
Authorization: Bearer <签名身份>
```

- 外部编号是客户在渠道中的编号，例如 Telegram 用户编号、公众号用户的 OpenID。
- 签名身份使用客户身份密钥按 HS256 签发，`sub` 为业务系统用户编号，并且必须包含 `channel_id`（渠道编号）与 `external_id`（外部编号），两者与请求地址一致。`name`、`email`、`attributes`、`tags` 的写法与网站挂件相同：`name` 写入客户名称，`attributes` 中与客户字段同名的取值写入客户资料，例如客户所属的代理。
- 设为已验证时，该账号的会话归入这位用户已有的客户资料；该账号尚未发来消息时同样生效。
- 撤销只在该账号当前验证为 `sub` 所指的用户时生效。
- 业务系统转发方式和网站挂件的每条消息自带签名身份，验证状态随消息更新，不使用本接口；以业务系统转发方式接入的渠道调用本接口返回 404。

| 响应状态 | 含义 |
| --- | --- |
| 204 | 已处理 |
| 400 | 渠道编号或外部编号格式不正确 |
| 401 | 签名身份缺失、无效、已过期，或与请求地址不一致 |
| 404 | 渠道不存在、已停用或不支持该接口 |
