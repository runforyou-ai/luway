title: 平台模型服务

---

平台管理员可以为整个平台配置模型，所有工作区都能直接选用，不需要各自接入模型供应商。入口在「设置 → 平台」下的「平台模型」「平台供应商」和「模型调用」。

## 供应商

平台供应商是平台模型背后真正提供服务的模型供应商，比如 OpenRouter、DeepSeek 或阿里云百炼。

1. 打开「平台供应商」，点击右上角的添加按钮，选择品牌。
2. 填写名称、API 密钥和 API 地址，可以先点「测试连接」确认配置可用。
3. 保存后，这个供应商就可以作为平台模型的来源。

平台供应商的密钥和地址只有平台管理员能看到，工作区成员看不到。仍是某个平台模型来源的供应商不能删除，需要先在平台模型中移除对应的来源。

## 模型目录

平台模型是工作区看到的模型，比如「DeepSeek V4.1 Flash」。一个平台模型可以配置多个来源，工作区只看到模型名称，不会看到背后用了哪些供应商。

1. 打开「平台模型」，点击右上角的添加按钮。
2. 添加来源：选择平台供应商，填写该供应商的模型标识，也可以点击来源后的列表按钮，从供应商可提供的模型中选择。模型名称为空时，会同时带入所选模型的类型、输入类型和 Token 上限。
3. 按需调整模型名称、类型、输入类型、上下文窗口和最大输出 Token 数。

调用时从第一个已启用的来源开始，这个来源请求失败后会尝试下一个。用上下箭头调整顺序，取消「启用」可以临时停用某个来源。所有来源都停用时，工作区暂时无法使用这个模型。

> [!IMPORTANT]
> 同一个平台模型的各个来源必须是同一个模型。向量化模型尤其如此：知识库的索引不会因为来源变化而重建，换成不同的模型会导致检索结果错误。

平台模型保存后立即对所有工作区可用。正在被工作区的 AI 员工、知识库或客服设置使用的平台模型不能删除，也不能改成不满足这些用途的类型或输入类型。

## 工作区如何使用

工作区在选择模型的地方（AI 员工、知识库、会话小结、翻译等）会看到「平台模型」分组，排在工作区自己配置的模型前面。工作区自配的模型服务见[模型服务](/docs/zh-cn/guide/workspace/models/)。

## 调用记录与错误

「模型调用」列出各工作区调用平台模型的记录，可以按模型、状态和工作区筛选。点开一条记录可以看到：

- 调用所属的工作区、用途和发起方；
- 耗时和 Token 用量；
- 每一次上游尝试使用的供应商、模型标识、状态和失败原因。

一次调用尝试了多个来源时，说明前面的来源请求失败、由后面的来源完成或最终失败。经常出现在同一个来源上的失败，通常需要检查该供应商的密钥、余额或模型标识。

工作区自配模型的调用记录属于工作区自己的数据，不会出现在这里。
