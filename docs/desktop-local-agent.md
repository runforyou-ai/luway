# Luway 助理与桌面端本地运行实施方案

状态：实施中  
日期：2026-09-23  
范围：助理（成员本人创建、绑定自己电脑的 AI）的产品形态、交互与桌面端本地运行（P4）  
关联：本文是 [Luway 路线图](roadmap.md) 登记的独立方案，设计细节只保留在本文；助理与 AI 员工在工作台中的展示位置见 [工作台信息架构与服务对象扩展方案](workbench-ia.md)

成员在自己的电脑上创建助理，助理在主人的电脑上查阅和整理资料、修改文档与表格、改代码，并可以通过对话安装和使用技能。助理默认使用企业模型服务，开箱即用；电脑上已装好支持 ACP 的编程 Agent（如 Codex）的成员，可以让助理交给它完成。主人可以在任意端和助理对话；把助理带进群里后，群成员都可以让它在主人的电脑上工作。本文是主要参考，不构成强制约束，实施中按更合适的做法调整并同步更新；已交付的部分以代码为准，本文只保留后续批次的设计，全部交付后连同路线图中的对应条目一并删除。

## 产品定义

### 定位

助理面向企业里的普通成员，不要求使用者懂技术。它的价值是把「让 AI 在我电脑上干活」放进协作会话：任务从聊天发起，过程和结果留在会话里，同事可以在群里请主人的助理帮忙。

- 默认使用内置运行时与企业模型服务，成员不需要安装或登录任何额外工具。
- 主人电脑上已有支持 ACP 的本机 Agent 时，可以改由它完成工作。ACP 生态以编程类 Agent 为主，面向普通成员的办公应用（如 WorkBuddy 桌面端）未开放 ACP，因此本机 Agent 是给已在使用编程 Agent 的成员的补充选项，普通成员使用默认来源。

### 两类 AI

| | AI 员工 | 助理 |
| --- | --- | --- |
| 归属 | 企业，由管理员创建 | 成员本人创建，一个成员可以有多个 |
| 执行位置 | 服务端 | 只在主人绑定的那台电脑上 |
| 操作电脑 | 不能 | 能 |
| 模型 | 企业模型服务 | 企业模型服务，或主人电脑上的本机 Agent |
| 在线 | 始终可用 | 绑定的电脑在线且未暂停 |
| 服务会话 | 可以接待客户、员工、伙伴 | 不能接待，与助理的对话不产生服务周期 |
| 内部单聊与群聊 | 可以 | 只进入主人所在的会话 |
| 通讯录 | 不列入；服务对象含本企业员工的以服务台列在同事中 | 挂在主人名下展示 |

执行位置由归属决定：AI 员工永远在服务端执行，助理永远在主人的电脑上执行。同一个 AI 不会因为触发者或会话不同而切换模型来源或执行位置。

### 命名与界面用词

界面统一称「助理」，展示为「<主人姓名>的助理 · <助理名称>」，例如「张三的助理 · 小码」。英文界面使用 `Assistant`。

过程展示用白话描述助理在做什么，命令原文、完整参数等技术细节折叠在「详情」中。本机 Agent 以产品名展示，例如「由电脑上的 Codex 完成」；展示名服从该产品的品牌条款。

### 助理跟随主人

助理在主人的电脑上执行、动的是主人的文件，因此：

- 助理只出现在主人所在的会话中。其他成员不能与别人的助理单聊，只能在主人也在的群里使用它。
- 只有主人能把自己的助理加入群聊。
- 主人退出群聊时，其名下助理同时退出该群。
- 主人被停用时，其名下助理全部停用并退出所有群聊；主人恢复后助理保持停用，由主人重新启用。
- 助理不能接待客户，也不能被加入客户会话。

成员都可以创建助理，企业不设总开关；管理员可以停用单个助理。

## 交互

### 单聊

- 在绑定电脑上实时展示运行过程；其他端展示运行状态与最终回复。

### 默认文件夹

- 每个会话在绑定电脑上有一个默认文件夹，位于用户文档目录（macOS 为「文稿」，Windows 含 OneDrive 重定向后的位置，Linux 按 XDG 用户目录）下的 Luway，首次运行时自动创建，创建失败只影响文件工具；主人参与该会话的助理共用。它是命令的工作目录，也是生成文件的默认位置。
- 不单独指定文件夹：用户在对话中提到哪个文件夹，助理就去哪里工作。文件工具使用电脑上的真实路径，相对路径以默认文件夹为起点。

### 群聊

- 群成员选择器中，主人能看到并添加自己的助理；其他成员看不到别人的助理。
- @ 助理与 @ AI 员工交互一致，群成员都可以触发助理，能力与主人触发相同。助理之间、助理与 AI 员工之间按现有轮次规则接力，各助理在各自主人的电脑上执行。
- 主人可以随时把自己的助理移出任何群，群主可以移出群内任何助理。

### 各端差异

| | 绑定电脑上的桌面端 | 其他桌面端 | Web 与移动端 |
| --- | --- | --- | --- |
| 创建、换电脑 | 可以 | 可以（换到这台电脑） | 不可以 |
| 与助理对话 | 可以 | 可以 | 可以 |
| 运行过程 | 实时流式 | 状态与最终回复 | 状态与最终回复 |

## 架构

```text
服务端
├── 发送事务与群聊轮转：助理的 Run 写入执行设备（助理绑定电脑），不投递服务端任务
├── 设备工作通知：提交后经成员事件流推送 device_work_advanced
├── 领取与续租：设备领取 Run 并取得租约，续租响应回带取消状态
├── 运行期服务：Peek／Claim 读取 Lane 输入、知识检索、联网搜索、附件读取、企业 MCP 工具列出与调用
├── 模型代理：校验 Run、设备与租约后注入供应商凭据并透传流式响应
└── 收尾：result 与 failure 两个入口进入既有结果事务，群聊在同一事务提取点名并轮转

桌面端 Go
├── 设备注册与领取循环：独立定时器加事件流唤醒
├── agentruntime：与服务端同一份代码，用于企业模型服务来源
├── ACP 客户端：经 coder/acp-go-sdk 以 stdio 驱动本机 Agent 或其适配器进程
├── 远程适配器：InputFeed、知识检索、联网搜索、附件读取、企业 MCP 工具，模型 BaseURL 指向服务端代理
├── 本机工具：localworkspace 提供本机文件读写与命令执行
├── 技能：~/.luway/skills 与跨工具技能目录，运行时按需加载
└── 本机运行流：本机界面查看本机执行中的运行时直接订阅本机过程流
```

## 不变量

- **执行位置由归属决定。** AI 员工的 Run 只在服务端执行，助理的 Run 只派发到助理绑定的电脑。
- **运行时同一份。** 企业模型服务来源的助理与服务端执行同一份 `internal/integration/agentruntime` 代码，有效配置由同一个解析器 `ResolveAssignment` 产出。执行侧能力只影响工具清单、指令中的工具说明和 MCP 服务名称。
- **业务事实只在服务端。** Run、Lane、Input、内容块、结果消息幂等和群聊轮转全部在服务端事务内完成，设备本地只保存设备注册。
- **企业凭据不下发。** 使用企业模型服务时，设备取得的配置不含模型凭据，模型调用经服务端代理；企业 MCP 服务的凭据同样只在服务端，设备经服务端代理列出和调用其工具。
- **订阅凭据不上行。** 本机 Agent 的登录与订阅凭据只由其自己管理，Luway 不读取、不保存、不上传。
- **文件位置由设备决定。** 默认文件夹位于用户文档目录下的 Luway，按会话编号命名，服务端不保存其位置；运行过程中访问过的路径与读取结果随过程内容回写，会话成员都能查看。
- **助理跟随主人。** 助理只作为参与者存在于主人所在的会话，主人离开即随之离开。
- **本机工具全部提供。** 设备执行的运行提供本机工具目录中的全部工具，桌面端与服务端随同一版本发布，不做版本协商。
- **同一默认文件夹同一时刻只有一个运行。** 服务端按执行范围限定排队中与运行中的 Run 最多一个，单聊与群聊的执行范围即会话，同一会话的助理不会同时改动默认文件夹。
- **有意终止是终局。** 停止和租约过期后的 Run 不自动续跑，本机改动可能已经发生。

## 数据模型

- `trust_level` 与服务端 Agent 调用设备用的 `capability_manifest` 随 P2 增加。

## 本机工具

### 技能

- 项目级 `.agents/skills/` 暂不读取：助理的工作文件夹不固定，且项目内的技能可能来自不可信的仓库；出现在代码仓库中工作的场景后，随「信任的文件夹」一并提供。

### 工具扩展规则

- 启用后台命令时，后台任务生命周期绑定在 Run 上，Run 结束即终止。
- 增加单轮模型静默超时时单独命名，不复用设备租约续期间隔、本地 Run 总时限与单次命令预算。

## 本机 Agent

Codex 已接入，其余本机 Agent 沿用同一套 ACP 客户端，逐个补探测与启动配置：

- 需要适配器的 Agent 固定适配器版本，安装到运行环境目录并随桌面端升级，使用主人已安装的 CLI 及其登录状态；登录状态由该 Agent 自己的命令判断，Luway 不读取其凭据。
- 接入前逐个核实条款，核对范围包括：订阅登录能否经第三方客户端使用，以及由第三方客户端自动批准其工具调用是否仍在允许范围内。条款未明确的 Agent 不排入交付批次；条款变化时同步调整下表。

### 接入与条款

核对日期：2026-09-27。

| 本机 Agent | 接入方式 | 条款现状 | 批次 |
| --- | --- | --- | --- |
| Codex | 适配器 `@agentclientprotocol/codex-acp` | OpenAI 支持第三方工具使用 ChatGPT 订阅（[Zed 公告](https://zed.dev/blog/chatgpt-subscription-in-zed)） | 已接入 |
| Claude Code | 适配器 `claude-agent-acp`，基于 Agent SDK | 未经批准的第三方产品不得提供 claude.ai 登录或订阅额度，界面不得使用「Claude Code」名称（[Agent SDK 概览](https://code.claude.com/docs/en/agent-sdk/overview)）；订阅经 ACP 使用的计费方案暂停待修订（[帮助中心](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)） | 暂缓，Anthropic 公布修订后的方案后再核实 |
| Gemini CLI | 原生 ACP 模式 | 禁止第三方软件借用其 OAuth 直接访问后台（[条款](https://geminicli.com/docs/resources/tos-privacy/)），未就启动官方 CLI 的编排类客户端表态 | 待核实 |
| CodeBuddy CLI | 原生，`codebuddy --acp` | 企业版文档说明了 ACP 集成（[文档](https://cloud.tencent.com/document/product/1831/137021)），个人订阅是否允许第三方驱动未见说明 | 待核实 |
| OpenCode、Qwen Code、Kimi CLI 等原生 ACP Agent | 原生 | 未逐个核实 | 待核实 |

WorkBuddy 桌面端与 CodeBuddy CLI 是两条路径：桌面端是面向普通成员的办公应用，未开放 ACP；CodeBuddy CLI 是同一底座的命令行 Agent，按上表核实后接入。

## 交付批次

**本机 Agent：其他。** 「接入与条款」表中核实通过的 Agent 逐个补探测与启动配置，每个 Agent 单独验收：完成任务并回复、未登录时提示、停止后其进程及子进程全部终止、订阅凭据不出现在设备侧上报与服务端。

界面操作（截图、鼠标与键盘输入）暂缓，出现明确场景后随 macOS 辅助功能与屏幕录制授权引导一起交付。

改动前确认、群成员的权限区分、可访问文件范围、操作系统级沙箱与设备密钥签名等安全能力，准备正式上线时随安全专项统一设计。

## 验收边界

- AI 员工只在服务端执行，助理只在绑定电脑上执行。
- 助理不出现在主人不在的会话和任何客户会话中。
- 停止后命令进程组、本机 Agent 进程及其子进程终止。
- 设备侧不出现企业模型供应商凭据，服务端不出现本机 Agent 订阅凭据。
- 相对路径与命令工作目录都以会话的默认文件夹为准。
- 设备撤销后不能调用模型代理。
- 服务端与设备对同一 Run 解析出同一份有效配置。

## 不做的事

外部编辑器经 ACP 调用 Luway、移动端本地运行、设备端本地模型与离线运行、跨设备迁移进行中的 Run、唤醒或控制离线的电脑、其他成员邀请别人的助理进群、设备侧本地知识库。

## 未决

- 设备侧运行时崩溃与桌面端主进程崩溃的区分上报方式。
- 附件在设备与模型代理之间的二次搬运是否需要由代理直接注入。
- 本机 PDF 的读取方式：模型输入模态尚无 PDF，`read_file` 目前只按图片读取 PNG、JPEG、GIF、WebP。
