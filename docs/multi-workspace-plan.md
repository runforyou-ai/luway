# 多工作区与账号模型方案

状态：阶段四、五待实施
日期：2026-09-29
范围：官方托管的账号与权益接入、统一权益与商业化边界、自定义域名
关联：本文取代 [官方托管服务建设方案](saas-hosting-plan.md) 中关于企业域名、租户解析、身份绑定、成员邀请和企业开通的设计，见第 5 节

部署级账号、多工作区、账号会话与工作区识别、首次安装、注册开关、成员邀请、三端入口和官方账号的 Web 登录已交付，以代码为准。本文只保留后续阶段的设计。

## 1. 官方托管

- 原生端官方账号登录：连接官方托管部署时，桌面端与移动端在系统浏览器中完成官方身份授权，授权回调使用部署地址下的声明式链接（iOS Universal Links、Android App Links），声明文件由部署地址提供。登录尝试的客户端类型为 `desktop` 或 `mobile`。当前原生端连接托管部署时提示暂不支持官方账号登录。
- 邀请衔接：未登录的受邀人在邀请页通过官方账号登录后回到邀请页确认加入，接受规则与自托管相同，并要求官方身份的邮箱已验证。登录尝试的 `accept_invitation` 用途是否保留，按实施时的邀请页流程确定。
- 工作区在 Luway 内创建。订阅按工作区计费（套餐加席位），由工作区管理员账号付费；权益由 SaaS 按工作区同步到 `organization_entitlements`，沿用权益版本与对账机制。账号只受免费工作区数量上限约束，上限由 SaaS 按账号下发，托管部署创建工作区前检查该上限。无效权益下的工作区按生命周期规则限制使用。
- SaaS 承担官方账号、订阅与账单，不承担开通流程；官网提供进入部署地址的入口。运营 API 在现有部署与工作区查询之外，增加按工作区的权益同步与按账号的免费工作区上限同步，具体契约在本阶段实施前确定。
- 托管部署在工作区切换器中提供账号与订阅入口。

## 2. 统一权益

席位上限、功能开关、AI 额度和有效期都通过同一个权益结构检查，两种部署只有权益来源不同：

| 来源 | 适用 | 内容 |
| --- | --- | --- |
| 默认权益 | 自托管 | 席位不限，开源功能全部可用，企业功能关闭 |
| 授权文件 | 自托管企业版 | 官方私钥签名，服务端用内置公钥离线校验，打开对应企业功能并给出有效期 |
| SaaS 同步 | 官方托管 | 按工作区的套餐快照 |

## 3. 商业化边界

- 代码保持 Apache 2.0。核心业务功能（收件箱、渠道、成员、多工作区、AI 助理框架）在两种部署中完整可用，两种部署不以功能删减区分。
- 官方托管收入：工作区订阅；内置 AI 模型额度，超出部分按量计费；运维、备份、邮件、对象存储、证书和服务承诺包含在订阅中。
- 自托管收入：企业功能授权（SAML 单点登录、审计日志、细粒度权限、数据保留策略、部署级管控、高可用部署支持）和私有化实施与支持合同。企业功能同为 Apache 2.0，授权文件用于商业交付与支持，不作为技术保护手段。
- 移动端推送：官方发布的移动端使用官方推送证书，自托管部署向官方移动端推送经官方推送中继，免费额度内可用，企业授权或托管订阅不限量；自行构建移动端的部署使用自己的推送证书，不经过中继。
- 官方桌面端与移动端的同一个安装包既能连接官方托管，也能连接任意自托管部署。

## 4. 自定义域名

- 数据模型：`organization_domains` 记录 `host`（全部署唯一）、`organization_id`、`verification_token`、`verified_at`。一个工作区可以绑定多个域名，同一域名只能被一个工作区验证。
- 验证：工作区管理员在工作区设置中添加域名，服务端生成 TXT 验证记录；用户添加 DNS 记录后发起验证，通过后写入 `verified_at`。只有验证通过的域名参与识别、链接生成和证书申请。
- 工作区识别：访问地址是已验证的自定义域名时，工作区由域名确定，请求显式给出的工作区必须与之一致；其他访问地址沿用请求中的工作区编号。
- Web 路由：自定义域名下工作区内页面不加 `/w/<工作区标识>` 前缀，工作区由域名确定。部署探测在自定义域名下额外返回该工作区名称与标识。
- 链接：服务端生成的绝对链接（客户续聊链接、Agent 附件地址、邀请链接）优先使用工作区已验证的自定义域名，没有时使用部署地址。对外访客页面、挂件和 Webhook 继续按路径中的渠道编号确定工作区，与访问地址无关。
- 证书：`TLS_MODE=auto` 时按已验证的自定义域名和部署地址申请证书；`TLS_MODE=external` 时由前置入口负责证书。
- 官方托管部署中，已验证的自定义域名的 Web 登录回调追加到官方身份服务的 Web 客户端；部署地址的回调在部署时登记一次。
- 删除域名后，该域名不再参与工作区识别和链接生成。

## 6. 实施阶段

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 四：官方托管 | 原生端系统浏览器授权、官方账号接受邀请、按工作区订阅与免费工作区上限、SaaS 调整 | 官方账号在 Web 与原生端登录并创建、切换工作区 |

## 7. 验收要求

- 自定义域名下请求显式给出的工作区与域名不一致时被拒绝。
- 对外访客页面与 Webhook 在部署地址和自定义域名下都能按渠道工作。
- 托管部署中官方账号在 Web、桌面端和移动端都能登录，超过免费工作区上限时不能再创建工作区。
